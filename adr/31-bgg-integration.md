# 31. BGG integration: suggestions and box-art enrichment via the XML API

Date: 2026-10-06 (suggestion rework: 2026-10-11; art refresh rework: 2026-10-26)

## Context

The games catalogue stores `bgg_id`/`tesera_id` (migration 062); Tesera provides discovery (name search) and the localized Russian titles, but its box-art thumbnails are small and the API is undocumented with no SLA. BoardGameGeek is the precise source: exact lookups by the stored `bgg_id`, canonical English names, localized titles as alternate names, and full box art. In 2025 BGG moved the XML API behind application registration — every request needs a Bearer token issued per registered application ([usage guide](https://boardgamegeek.com/using_the_xml_api), [Terms of Use](https://boardgamegeek.com/wiki/page/XML_API_Terms_of_Use)). Tesera's DDoS-Guard, meanwhile, increasingly serves its JS challenge to non-browser clients, so anything gated solely on Tesera fails at the worst times.

## Decision

**Client-side BGG calls are out; the Go backend owns the token.** BGG's terms mandate server-side, cached, minimal-traffic usage and revoke exposed tokens; the frontend is a static export and cannot hold a secret anyway. The token lives in the environment (`ELO_WEB_SERVICE_BGG_API_ACCESS_TOKEN`, optional — empty disables the feature entirely, same degradation as the Tesera client).

**Enrichment persists URLs; pages never call BGG** ("cache, don't hot-fetch"). Art refreshes whenever a `bgg_id` is written or changed — create, metadata edit, auto-match: the write clears both image columns and a background `/xmlapi2/thing` fetch (≤20 ids per call, ≥5 s between requests per BGG's guidance) refills them after commit, so stale art from an old id cannot linger. For art that is wrong while the id is right, `POST /games/{id}/bgg-refresh-art` (editor-gated, called from the admin game-edit dialog's «Обновить обложку» button) overwrites whatever URLs are stored; a reason rides along when BGG knows no such thing or carries no art. Every URL change is audited (From→To); failures never block the underlying write. The URLs land in `games.image_url` / `games.image_thumb_url` (migration 065) and flow to the frontend on the normal game reads. The earlier bulk `POST /games/bgg-enrich` backlog action is gone: its "games still missing art" badge was misleading (it counted only imageless rows, never wrong ones), and every path that writes a `bgg_id` now refreshes on its own.

**Images are hotlinked, never copied.** The Terms of Use license the API *data* and are silent on images — box art remains the rightsholders' property hosted by BGG. Hotlinking `cf.geekdo-images.com` keeps hosting and attribution with BGG, avoids any "modifying data" concern, and self-heals: a stale URL is repaired by the next enrichment run. The service worker caches the images (`CacheFirst`, 30 days) so pages stay fast and offline-capable.

**Attribution: name credit + official logo.** The Terms of Use require crediting BoardGameGeek by name and, for public-facing apps, displaying the official "Powered by BGG" logo linked back to BGG (files from BGG's official logo kit, light and reversed variants in `nextjs/public/bgg/`). Both sit in the global site footer: the data credit text («Данные об играх — BoardGameGeek») next to the logo.

**Tokens are per environment.** localhost, stage and prod each use their own token under the one registered application: per-token usage stats on the Applications page map to environments, and rotating a leaked dev token never touches prod. Stage and prod secrets ship via sops (`secrets.env` per deployment), localhost overrides via the gitignored `.env.local`.

**Division of labor with Tesera.** BGG is the primary suggestion source: `GET /games/suggestions` searches `/xmlapi2/search` and enriches the matches via batched `/thing` requests, which carry the canonical English titles. The localized Russian title prefers Tesera: its rows are curated for the Russian audience and keep the full form (e.g. «Eclipse. Второй рассвет галактики»), while BGG's `pkg/bgg.PickRussianName` attributes the thing's language-less alternate names by script (Russian-only letters push a candidate up, Ukrainian/Serbian-exclusive letters rule it out; mixed-script alternates reduce to their Cyrillic run, so «Catan (Колонизаторы)» folds to «Колонизаторы») — it fills in only when the attached Tesera row has no localization. Tesera also adds its own rows for games BGG lacks and remains the auto-match source. Both catalogues are queried in parallel under one deadline (Tesera's guard retries alone can stretch a sequential run into minutes). Ranking is tiered against the query — exact normalized match, word-boundary prefix, contains — with base games before additions within a tier: a search for "eclipse" must surface the base games «Eclipse» and «Eclipse: Second Dawn for the Galaxy», not a flood of same-prefix expansions (BGG's own search order cannot be trusted to do that within a bounded result window). A catalogue failing alone degrades the suggestion list (reported via `tesera_unavailable`/`bgg_unavailable` flags) — the picker keeps working while Tesera is guarded. Search answers are cached server-side (in-memory TTL) because the endpoint fires per debounced keystroke.

## Consequences

- `pkg/bgg` mirrors `pkg/tesera`: a minimal client whose failures degrade to "no data".
- Suggest traffic is bounded (one `/search` + one batched `/thing` per query, cached 15 min; the dedup-by-id search window is exactly one thing batch), so editor usage stays within BGG's traffic guidance.
- The script heuristics are conservative: ambiguous Russian alternates (e.g. Carcassonne's «Каркасон»/«Каркассон» plus its old «Средневековье» re-theme) resolve to no name and fall back to Tesera or the admin.
- An auto-match never erases an existing `bgg_id` when the Tesera match knows no BGG link (full-state patch carries the old reference through), so it never strands art either.
- If BGG revokes the license or the token, the feature switches off by removing the token; stored URLs keep rendering, and suggestions degrade to Tesera with the `bgg_unavailable` flag.
